📦 CSS Margin-Inline & Margin-Block

Logical Properties for Direction-Aware Spacing

Master inline and block axis margins for better internationalization and layout control

LOGICAL What are Logical Properties?

Logical properties define spacing based on content flow direction rather than physical directions (left/right/top/bottom).

Two Axes Explained

  • Inline axis: Direction text flows (left-right in English, right-left in Arabic)
  • Block axis: Direction paragraphs stack (top-bottom in all languages)

Why Logical Properties?

  • Internationalization: Single CSS works for all text directions
  • Maintainability: Easier to understand spacing intent
  • Future-proof: Works with vertical writing modes
  • Cleaner code: Less direction-specific overrides
ℹ️ Key Concept: Instead of left/right/top/bottom, think inline-start/inline-end/block-start/block-end.

📐 Understanding the Axes

Visualize how inline and block axes work in different writing modes:

English (Horizontal LTR)

inline →
↓ block

Inline: left to right | Block: top to bottom

Arabic (Horizontal RTL)

← inline
↓ block

Inline: right to left | Block: still top to bottom

✨ Advantage: Same CSS works for both languages! No need for separate stylesheets.

↔️ Margin-Inline Properties

Control spacing on the inline axis (left-right in English, right-left in Arabic).

Syntax

element {
  margin-inline: value;
  margin-inline-start: value;
  margin-inline-end: value;
}

Values & Examples

  • margin-inline: Sets both start and end
  • margin-inline-start: Left in LTR, right in RTL
  • margin-inline-end: Right in LTR, left in RTL

Example

.card {
  /* English: left & right margin */
  margin-inline: 20px;
}

/* Automatically adapts to RTL! */
Element with margin-inline: 30px

⬍ Margin-Block Properties

Control spacing on the block axis (top-bottom in most writing modes).

Syntax

element {
  margin-block: value;
  margin-block-start: value;
  margin-block-end: value;
}

Values & Examples

  • margin-block: Sets both start and end
  • margin-block-start: Top margin
  • margin-block-end: Bottom margin

Example

h1 {
  /* Top & bottom margin */
  margin-block: 1em 0.5em;
}
Element with margin-block: 30px 15px

🔄 Physical vs Logical Properties

Use Case Physical (Old Way) Logical (New Way) Benefit
Horizontal spacing margin-left, margin-right margin-inline-start, margin-inline-end Works with all text directions
Vertical spacing margin-top, margin-bottom margin-block-start, margin-block-end Works with vertical text
Symmetric horizontal margin: 0 20px margin-inline: 20px Clearer intent
Both axes margin: 10px 20px margin-block: 10px; margin-inline: 20px; More readable
ℹ️ Note: Physical properties (margin-left, etc.) still work. Logical properties are an alternative approach.

📋 Shorthand Value Patterns

Single Value margin-inline: 20px

Applies to both start and end (symmetric)

Two Values margin-inline: 10px 20px

First: start, Second: end

With Block margin: 10px; margin-inline: 20px

Override specific axis

🎨 Practical Examples

Example 1: Centered Card with Logical Margins

Using margin-inline for centering

.card {
  width: 400px;
  /* Center horizontally in all text directions */
  margin-inline: auto;
  /* Vertical spacing */
  margin-block: 2em;
}

Example 2: Typography with Logical Margins

Paragraph spacing independent of direction

p {
  margin-block-start: 1em;
  margin-block-end: 1em;
  margin-inline: 0;
}

Example 3: Bilateral List with Logical Margins

List that works in LTR and RTL

li {
  /* Indent in flow direction */
  margin-inline-start: 2em;
  /* Space between items */
  margin-block-end: 0.5em;
}

Example 4: Responsive Margins with Logical Properties

Mobile-first with logical values

section {
  margin-inline: 1em;
  margin-block: 1.5em;
}

@media (min-width: 768px) {
  section {
    margin-inline: 3em;
    margin-block: 2em;
  }
}

🏆 Best Practices & Tips

✅ Do:

  • Use for new projects: Future-proof your CSS
  • Combine with padding: Use logical padding too
  • Use in design systems: Make components multilingual
  • Migrate gradually: Mix physical and logical
  • Document intent: Comment why you're using logical
  • Test with RTL: Verify behavior in both directions

❌ Don't:

  • Mix directions inconsistently: Keep it uniform
  • Forget about physical properties: Sometimes still needed
  • Ignore browser support: Check your target browsers
  • Assume all developers know: Document clearly
  • Use alone in legacy projects: Combine with physical
  • Forget mobile testing: Test on all devices
⚠️ Important: Physical properties (margin-left, etc.) still work and are still valid. Use logical properties for new code, but don't break legacy implementations.

🔄 Migration from Physical to Logical

❌ Physical Properties
.element { margin-left: 20px; margin-right: 20px; margin-top: 10px; margin-bottom: 10px; }

Works only in LTR, needs RTL override

✅ Logical Properties
.element { margin-inline: 20px; margin-block: 10px; }

Works in any direction automatically

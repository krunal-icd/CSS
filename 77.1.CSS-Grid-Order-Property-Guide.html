CSS Grid: Order Property

Reorder grid items visually independent of HTML source order

Understanding the Order Property
What is Order?
order: A CSS property that reorders grid items visually without changing the HTML source order. Items are displayed in order value sequence (lowest to highest), not DOM order.
Key Characteristics
  • Visual Reordering Only: Doesn't change source code or accessibility order
  • Numeric Values: Uses integers (positive, negative, or zero)
  • Default Value: 0 for all items by default
  • Works with auto-placement: Respects auto-placement and explicit positioning
  • Flexbox Compatible: Same order property works with Flexbox too
  • No Performance Impact: Reordering doesn't affect layout calculations significantly
Visual Example
HTML Source Order: 1, 2, 3, 4, 5, 6 Default Display (order: 0 for all): ┌───┬───┬───┬───┬───┬───┐ │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ └───┴───┴───┴───┴───┴───┘ With Custom Order Values: Item 1: order: 3 Item 2: order: 1 Item 3: order: 4 Item 4: order: 2 Item 5: order: 0 Item 6: order: -1 Display Order: ┌───┬───┬───┬───┬───┬───┐ │ 6 │ 5 │ 2 │ 4 │ 1 │ 3 │ └───┴───┴───┴───┴───┴───┘ (Order: -1, 0, 1, 2, 3, 4)
Important: Accessibility Note
⚠️ Warning: The order property only affects visual order, NOT reading order for screen readers. Always ensure semantic HTML and logical source order for accessibility. Use order only for visual design enhancements, not for content hierarchy changes.
Syntax & Value Types
Basic Syntax
/* Default value */ order: 0; /* Positive values */ order: 1; order: 10; order: 999; /* Negative values */ order: -1; order: -10; /* Practical example */ .grid-item-first { order: 1; } .grid-item-last { order: -1; }
Value Types & Meanings
Value Type Example Display Position Use Case
Negative order: -1 Comes before items with order 0 or positive Moving items to beginning
Zero (Default) order: 0 Displays in source order among other 0 items Not specified (natural order)
Positive order: 1, 2, 10 Comes after items with lower order values Moving items to end or custom sequence
Large Positive order: 9999 Comes after all other items Forcing item to very end
Common Patterns
/* Pattern 1: Move one item to front */ .important-item { order: -1; } /* Pattern 2: Move one item to back */ .less-important-item { order: 999; } /* Pattern 3: Custom sequence */ .item-1 { order: 3; } .item-2 { order: 1; } .item-3 { order: 2; } /* Pattern 4: Responsive reordering */ @media (max-width: 768px) { .sidebar { order: 2; } .main { order: 1; } }
How Order Works with Grid Auto-Placement
Order Determines Auto-Placement Sequence
With auto-placement: Items are placed into grid cells in order value sequence, not source order. Lower order values are placed first.
Interaction with Explicit Positioning
Explicitly positioned items: Don't use auto-placement. They're placed at their specified grid-column/grid-row. Order still affects visual stacking (z-order) but not placement.
/* With auto-placement */ .grid { display: grid; grid-template-columns: repeat(3, 1fr); } .item-1 { order: 3; } /* Placed 3rd */ .item-2 { order: 1; } /* Placed 1st */ .item-3 { order: 2; } /* Placed 2nd */ /* Items placed: 2, 3, 1 (in order sequence) */
Order with Explicitly Positioned Items
.grid { display: grid; grid-template-columns: repeat(3, 1fr); } .item-1 { grid-column: 1; order: 3; /* Order doesn't affect placement here */ } .item-2 { grid-column: 2; order: 1; /* Placed at column 2 regardless of order */ } /* Items stay at col 1, 2, 3 despite order values */
Real-World Use Cases
Use Case 1: Responsive Reordering
Display sidebar last on mobile (below main content) but before main on desktop. Use order to change visual sequence at breakpoints.
.grid { display: grid; grid-template-columns: 1fr; } .main { order: 1; } .sidebar { order: 2; } /* Desktop: Sidebar first (left column) */ @media (min-width: 1024px) { .grid { grid-template-columns: 250px 1fr; } .sidebar { order: 1; } .main { order: 2; } }
Use Case 2: Featured Item First
Move featured or important item to the beginning without changing HTML. Perfect for dynamic content where featured status changes.
.grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); } .featured { order: -1; } /* Always first */
Use Case 3: Admin vs User Content
Show admin-only items first, then user items. Reorder based on user role without HTML changes.
.item { order: 10; } /* User items */ .item.admin { order: 0; } /* Admin items first */
Use Case 4: Priority-Based Display
Show high-priority items first, low-priority items last, based on data attributes or classes without changing source.
.item[data-priority="high"] { order: 1; } .item[data-priority="medium"] { order: 2; } .item[data-priority="low"] { order: 3; }
Best Practices & Important Considerations
✓ Do's
  • Use for visual reordering only: When display order differs from content importance
  • Keep semantic HTML: Maintain logical source order in HTML
  • Document order changes: Leave comments explaining why items are reordered
  • Test with screen readers: Ensure accessibility isn't broken by reordering
  • Use meaningful values: 0, 1, 2 or -1, 0, 1 rather than random numbers
  • Combine with responsive design: Change order at different breakpoints
  • Use for responsive layouts: Moving sidebars, changing column order on mobile
✗ Don'ts
  • Don't use order to fix poor HTML structure: Reorganize HTML if content hierarchy is wrong
  • Don't forget accessibility: Screen readers read source order, not visual order
  • Don't use large arbitrary numbers: Keep order values simple and meaningful
  • Don't rely solely on order for UX: Important items should be important in HTML too
  • Don't change semantic meaning: Order shouldn't make form inputs display before labels they describe
  • Don't use order with interactive elements carelessly: Can confuse keyboard navigation
Accessibility Warning
⚠️ Critical: The order property ONLY affects visual display. Screen readers, keyboard navigation, and form submission follow HTML source order. Never use order as a substitute for proper HTML structure. Always prioritize semantic HTML and logical source order.
Pro Tips
💡 Tip 1: Use order: -1 to move one item to the front. Simpler than assigning positive values to others.
💡 Tip 2: Use order with CSS custom properties for dynamic reordering: order: var(--item-order, 0);
💡 Tip 3: Combine order with auto-placement for powerful responsive layouts without changing HTML at breakpoints.
💡 Tip 4: Test keyboard navigation and screen readers when using order. Visual reordering can confuse assistive technologies.
💡 Tip 5: Consider using auto-placement with order instead of explicit grid-column/grid-row for more flexible layouts.

Quick Reference

order Property Basics:

  • Default value: 0 for all items
  • Reorders items visually, not in source code
  • Works with grid auto-placement
  • Doesn't affect reading order for screen readers

Common Syntax:

  • order: -1; (move to front)
  • order: 0; (default, source order)
  • order: 1; (move after default items)
  • order: 999; (move to end)

When to Use:

  • Responsive design (reorder at breakpoints)
  • Featured/priority items first
  • Role-based reordering (admin vs user)
  • Custom item sequences without HTML changes

📏 CSS Block-Size & Inline-Size

Logical Dimensions for Writing Mode Agnostic CSS

Master direction-aware width and height properties

LOGICAL What are Logical Dimensions?

Logical properties for width and height that adapt to text direction and writing mode instead of physical screen dimensions.

Key Concepts

  • inline-size: Width in LTR, height in vertical modes
  • block-size: Height in LTR, width in vertical modes
  • Direction-aware: Automatically adapts to writing mode
  • Future-proof: Works with vertical, RTL, and mixed text

Why Use Logical Sizing?

  • Global compatibility: Single CSS for all languages
  • Vertical text support: Works with Japanese, Chinese vertical
  • RTL languages: Automatic adaptation without overrides
  • Semantic clarity: Intent is clearer in code
ℹ️ Key Difference: width/height are physical, inline-size/block-size are logical and adapt to context.

↔️ Inline-Size Properties

Control the inline dimension (width in horizontal text, height in vertical).

Syntax

element {
  inline-size: value;
  min-inline-size: value;
  max-inline-size: value;
}

Properties Explained

  • inline-size: Sets dimension along inline axis
  • min-inline-size: Minimum inline dimension
  • max-inline-size: Maximum inline dimension

Examples

.container {
  inline-size: 500px;
}

.card {
  inline-size: 100%;
  max-inline-size: 400px;
}
Element with inline-size: 250px

⬍ Block-Size Properties

Control the block dimension (height in horizontal text, width in vertical).

Syntax

element {
  block-size: value;
  min-block-size: value;
  max-block-size: value;
}

Properties Explained

  • block-size: Sets dimension along block axis
  • min-block-size: Minimum block dimension
  • max-block-size: Maximum block dimension

Examples

section {
  block-size: 300px;
}

.hero {
  block-size: 100vh;
  min-block-size: 400px;
}
Element with block-size: 120px

🔄 Physical vs Logical Sizing

Horizontal text height height: 300px block-size: 300px Works in any mode
Constrain width max-width: 800px max-inline-size: 800px Respects writing mode

ℹ️ Note: Physical properties (width, height) still work. Logical properties are an alternative approach.

🎨 Practical Examples

Example 1: Responsive Container

Using logical sizes for flexible containers

.container {
  inline-size: 100%;
  max-inline-size: 1200px;
  block-size: auto;
  margin-inline: auto;
}

Example 2: Aspect Ratio with Logical Sizing

Images that maintain aspect ratio in any writing mode

img {
  inline-size: 100%;
  aspect-ratio: 16 / 9;
  block-size: auto;
}

Example 3: Square Elements

Creating perfect squares with logical properties

.square {
  inline-size: 200px;
  block-size: 200px;
}

Example 4: Min/Max Constraints

Flexible sizing with logical constraints

.flexible {
  inline-size: 50%;
  min-inline-size: 300px;
  max-inline-size: 900px;
  block-size: auto;
}

🏆 Best Practices & Tips

✅ Do:

  • Use for new projects: Build with logical properties
  • Combine with logical margins: Consistent approach
  • Test in multiple writing modes: Verify behavior
  • Use with aspect-ratio: Great combination
  • Document your approach: Help team understand
  • Migrate gradually: Mix physical and logical

❌ Don't:

  • Mix both approaches: Keep consistent
  • Forget aspect-ratio: Often works better together
  • Assume old browser support: Check your target
  • Use in isolation: Combine with logical margins
  • Skip mobile testing: Test all devices
  • Forget vertical text: Test Japanese/Chinese vertical
⚠️ Important: Physical properties (width, height) still work and are still valid. Use logical for new code, but don't break existing implementations.

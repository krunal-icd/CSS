CSS Quotes Property

Complete Guide to Typographic Quotation Marks

What is the Quotes Property?

The quotes property specifies what quotation marks should be used for the HTML <q> element and for the CSS open-quote and close-quote values. It allows you to define custom quote characters for different nesting levels, supporting multiple languages and typographic styles.

Key Purpose: The quotes property provides language-specific, typographically correct quotation marks that automatically adjust for nested quotes at different levels.

This property is essential for creating professional, language-aware typography in web applications. It separates content from presentation by letting CSS handle quote styling.

Syntax & Property Values

Basic Syntax

quotes: [open-level-1] [close-level-1] [open-level-2] [close-level-2] ... | none | initial | inherit;

Value Types

Value Type Description Example
string pairs Paired quote characters for each nesting level '"' '"' ''' '''
open-quote CSS value to insert opening quote via ::before content: open-quote;
close-quote CSS value to insert closing quote via ::after content: close-quote;
none Disable automatic quote insertion quotes: none;

Understanding Quotes

How Nesting Works

The quotes property accepts pairs of strings for each nesting level:

  • Level 1: First pair (outer quotes)
  • Level 2: Second pair (quotes inside quotes)
  • Level 3: Third pair (quotes inside level 2)
  • And so on for deeper nesting...

Example Structure:

:root { quotes: '"' '"' /* Level 1: double quotes */ ''' ''' /* Level 2: single quotes */ '«' '»' /* Level 3: guillemets */ }

Common Quotation Styles by Language

English (Double & Single)

:root { quotes: '"' '"' ''' '''; } /* Result: "quote with 'nested' quotes" */

German (Lower & Upper Guillemets)

:root { quotes: '„' '"' '‚' '''; } /* Result: „quote with ‚nested' quotes" */

French (Guillemets with Spaces)

:root { quotes: '« ' ' »' '"' '"'; } /* Result: « quote with "nested" quotes » */

Japanese (Corner Brackets)

:root { quotes: '「' '」' '『' '』'; } /* Result: 「quote with 『nested』 quotes」 */

How the Quotes Property Works

With HTML <q> Element

The <q> element automatically uses quotes defined in the quotes property:

<q>Hello world</q> renders as: Hello world

With CSS open-quote & close-quote

You can manually add quotes using content property:

span::before { content: open-quote; } span::after { content: close-quote; }

Nesting Behavior

When quotes are nested, they automatically use the appropriate level:

  • First level of <q> uses the first pair
  • <q> inside <q> uses the second pair
  • And so on for deeper nesting

Practical Code Examples

Example 1: English with Nested Quotes

:root { quotes: '"' '"' ''' '''; } q { font-style: italic; } /* HTML: */ <q>She said, <q>Hello world</q></q> /* Result: "She said, 'Hello world'" */

Example 2: Multiple Language Support

:root { quotes: '"' '"' ''' '''; } :lang(fr) { quotes: '« ' ' »' '"' '"'; } :lang(de) { quotes: '„' '"' '‚' '''; }

Example 3: Custom Quote Styling with CSS

:root { quotes: '"' '"' ''' '''; } blockquote { padding-left: 20px; border-left: 4px solid #667eea; } blockquote::before { content: open-quote; font-size: 2em; opacity: 0.5; margin-right: 5px; }

Example 4: Disable Quotes

q { quotes: none; } /* Removes automatic quote insertion from q elements */

Example 5: Custom Quote Characters

:root { quotes: '❝' '❞' '❛' '❜'; } /* Result: ❝Quote with ❛nested❜ quotes❞ */

Best Practices & Tips

✓ Best Practices:
  • Use appropriate quotes for the document language
  • Support nested quotes with multiple levels
  • Use :lang() selector for multi-language sites
  • Test with actual content to verify nesting behavior
  • Consider using semantic HTML <q> element
  • Combine with CSS styling for professional appearance
  • Use Unicode characters for special quote marks
⚠ Common Mistakes:
  • Using straight quotes instead of typographic marks
  • Not providing enough nesting levels for deep quotes
  • Forgetting to include both open and close quote for each level
  • Using curly quotes in source but expecting different output
  • Not testing with nested quote scenarios

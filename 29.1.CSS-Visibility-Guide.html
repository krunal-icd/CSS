Understanding CSS Visibility

The visibility property controls whether an element is visible or hidden. Unlike display: none which removes the element from layout, visibility: hidden hides the element but preserves its space in the layout.

Key Concept: Visibility hides an element but keeps its space reserved. The element is invisible but still takes up space in the document flow.

Visibility vs Display vs Opacity

Property Takes Space Hidden Interactive Use Case
visibility: hidden ✅ Yes ✅ Hidden ❌ No Reserve space, hide content
display: none ❌ No ✅ Hidden ❌ No Remove from layout
opacity: 0 ✅ Yes ✅ Hidden ✅ Yes Transparent, interactive
clip-path: polygon(0 0 0 0) ❌ No (visually) ✅ Hidden ❌ No Hide without space

When to Use Each

  • visibility: hidden: Hide element but keep layout intact
  • display: none: Completely remove from layout
  • opacity: 0: Make transparent but keep interactive
  • clip-path: Hide visually without taking space

The Visibility Property

Syntax

/* Basic values */
visibility: visible;     /* Default - element is visible */
visibility: hidden;      /* Element is hidden but takes space */
visibility: collapse;    /* Hide table rows/columns */

/* Global values */
visibility: inherit;     /* Inherit from parent */
visibility: initial;     /* Reset to default */
visibility: revert;      /* Revert to browser default */
visibility: unset;       /* Unset visibility */

1. Visibility: Visible (Default)

Element is visible and takes up space. This is the default value.

Visible Element

This element is visible and takes space

.element {
    visibility: visible;  /* Default */
}

2. Visibility: Hidden

Element is hidden but still takes up space in the layout. Good for preserving layout structure.

Normal Element
Hidden Element (but space reserved)
Normal Element
.element {
    visibility: hidden;  /* Hidden but space preserved */
}

Notice the middle element is hidden but its space is still reserved in the layout.

3. Visibility: Collapse

Used for table rows and columns. Hides the row/column and removes it from table layout.

/* For table rows */
tr.hidden {
    visibility: collapse;
}

/* For table columns */
col.hidden {
    visibility: collapse;
}

Inheritance Behavior

Important: visibility is inherited from parent elements, but it can be overridden in children.

/* Parent is hidden */
.parent {
    visibility: hidden;
}

/* But child can be shown */
.parent .child {
    visibility: visible;  /* Shows this child despite parent being hidden */
}

Visibility vs Other Hiding Methods

Visibility: Hidden vs Display: None

visibility: hidden

  • ✅ Element takes space
  • ✅ Layout is preserved
  • ❌ Element is hidden
  • ❌ Not interactive
  • ⚡ Faster than display changes (in some cases)
.hidden {
    visibility: hidden;
}

/* Space is still reserved! */

display: none

  • ❌ Element takes no space
  • ❌ Layout shifts
  • ✅ Completely removed
  • ❌ Not interactive
  • ⚡ Triggers layout recalculation
.hidden {
    display: none;
}

/* No space reserved! */

Visibility: Hidden vs Opacity: 0

visibility: hidden

  • ✅ Takes space
  • ❌ Not interactive
  • ✅ Truly hidden
  • ⚡ No interaction listeners
.hidden {
    visibility: hidden;
}

/* Element won't respond to clicks */

opacity: 0

  • ✅ Takes space
  • ✅ Still interactive
  • ✅ Transparent
  • ⚡ Good for transitions
.hidden {
    opacity: 0;
    pointer-events: none;  /* To prevent interaction */
}

/* Element will still respond to clicks unless pointer-events disabled */

Decision Tree

Do you want to hide AND remove from layout?

  • ✅ Yes → Use display: none
  • ❌ No → Continue...

Do you want the element to be interactive?

  • ✅ Yes → Use opacity: 0 with pointer-events: none
  • ❌ No → Continue...

Use visibility: hidden when:

  • You want to keep the element's space in layout
  • You don't want it to be interactive
  • You want to smoothly hide/show without layout shift

Real-World Examples

Example 1: Hidden Placeholder in Form

Hide but reserve space for error messages.

.form-error {
    visibility: hidden;  /* Space reserved */
    color: red;
    font-size: 0.85rem;
}

/* Show when there's an error */
.form-error.show {
    visibility: visible;
}

Example 2: Invisible Spacing Element

Use for layout alignment without showing content.

.spacer {
    visibility: hidden;
    height: 20px;
}

/* Alternative: use margin or padding instead */

Example 3: Hidden Column in Table

Hide table columns while preserving layout.

table tr td:nth-child(3) {
    visibility: hidden;  /* Column space is preserved */
}

/* Or collapse for complete removal */
table tr td:nth-child(3) {
    visibility: collapse;  /* Removes space from table */
}

Example 4: Conditional Visibility

Toggle visibility based on state.

.tooltip {
    visibility: hidden;
    position: absolute;
    background: black;
    color: white;
    padding: 8px 12px;
    border-radius: 4px;
}

.element:hover .tooltip {
    visibility: visible;
}

Example 5: Animation with Visibility

Show/hide with smooth transitions using visibility.

.modal {
    visibility: hidden;
    opacity: 0;
    transition: opacity 0.3s ease, visibility 0.3s ease;
}

.modal.open {
    visibility: visible;
    opacity: 1;
}

Example 6: Accessible Skip Link

Hide but keep accessible to screen readers.

.skip-link {
    position: absolute;
    left: -9999px;
    visibility: hidden;
}

.skip-link:focus {
    visibility: visible;
    left: 0;
}

Example 7: Loading Placeholder

Reserve space for loading content.

.content {
    visibility: hidden;
    min-height: 200px;
}

.content.loaded {
    visibility: visible;
}

Example 8: Responsive Menu Visibility

Show/hide menu based on screen size.

@media (max-width: 768px) {
    .desktop-menu {
        visibility: hidden;
        display: none;
    }
    
    .mobile-menu {
        visibility: visible;
    }
}

Quick Reference & Best Practices

Visibility Property Values

Value Effect Space Preserved
visible Element is shown N/A
hidden Element is hidden ✅ Yes
collapse Hide table rows/cols ❌ No (for tables)

Common Patterns

.hidden {
    visibility: hidden;
}
.element .hidden-content {
    visibility: hidden;
}

.element:hover .hidden-content {
    visibility: visible;
}
.element {
    visibility: hidden;
    opacity: 0;
    transition: all 0.3s ease;
}

.element.show {
    visibility: visible;
    opacity: 1;
}
.parent {
    visibility: hidden;
}

.parent .important {
    visibility: visible;  /* Shows despite parent */
}
.visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;
    border-width: 0;
}

Best Practices

  • ✅ Use visibility: hidden when you need to preserve layout
  • ✅ Use display: none when you want to remove from layout
  • ✅ Use opacity: 0 for smooth transitions
  • ✅ Combine with pointer-events: none to prevent interaction
  • ✅ Consider accessibility implications
  • ✅ Test with keyboard navigation
  • ❌ Don't use visibility: hidden for critical links
  • ❌ Don't hide form fields with visibility (use display: none)

Performance Considerations

  • Visibility changes: Fast, no layout recalculation
  • Display changes: Slower, triggers layout
  • Opacity changes: GPU accelerated
  • Multiple visibility changes: Use CSS classes or data attributes
  • JavaScript toggling: Batch DOM changes

Accessibility Tips

  • Use visibility: hidden for truly hidden content
  • Use display: none for UI chrome (decorative)
  • Use aria-hidden="true" for screen readers
  • Don't hide interactive elements needed for navigation
  • Provide alternative ways to access hidden content
  • Test with screen readers

Browser Support

  • ✅ visibility: visible - All browsers
  • ✅ visibility: hidden - All browsers
  • ✅ visibility: collapse - All modern browsers (tables)
  • ✅ visibility inheritance - All browsers

Common Mistakes to Avoid

  • ❌ Using visibility: hidden for critical navigation
  • ❌ Forgetting that space is still reserved
  • ❌ Not considering accessibility
  • ❌ Using visibility instead of display: none when space shouldn't be reserved
  • ❌ Hiding content that should be in tab order
  • ✅ Use the right tool for the job

Advanced Concepts

Visibility Inheritance

Visibility is inherited, but child elements can override it.

/* Parent hidden, child visible */
.parent {
    visibility: hidden;
}

.parent .child {
    visibility: visible;  /* This child is visible! */
}

/* But grandchild inherits from child */
.parent .child .grandchild {
    visibility: visible;  /* Inherits from child */
}

Combining with Other Properties

/* Visibility + Opacity for smooth transitions */
.element {
    visibility: hidden;
    opacity: 0;
    transition: visibility 0.3s ease, opacity 0.3s ease;
}

.element.show {
    visibility: visible;
    opacity: 1;
}

/* Visibility + Pointer Events for interaction control */
.element {
    visibility: hidden;
    pointer-events: none;
}

Table-Specific Use Case

/* Hide specific table column */
table th:nth-child(4),
table td:nth-child(4) {
    visibility: collapse;  /* Removes from table layout */
}

/* vs hiding without removing space */
table th:nth-child(4),
table td:nth-child(4) {
    visibility: hidden;    /* Keeps space in table */
}

Screen Reader Accessibility

/* Method 1: CSS visually hidden but accessible */
.sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    border: 0;
}

/* Method 2: ARIA hidden */
.decorative {
    aria-hidden: true;
}

/* Method 3: Visible to screen readers but visually hidden */
.element {
    visibility: hidden;
    /* Screen readers still announce this! */
}

CSS Padding-Inline & Padding-Block Tutorial

📚 Introduction

Padding-inline and padding-block are logical CSS properties that add space inside an element, but they're relative to the element's writing direction rather than physical sides.

💡 Tip: These properties are writing-direction aware, making them perfect for multilingual websites!

🎯 Padding-Inline vs Padding-Block

Padding-Inline

Controls padding on the inline axis (left-right in LTR languages, right-left in RTL languages).

padding-inline: 20px; /* Left & Right in LTR */

Padding-Block

Controls padding on the block axis (top-bottom regardless of text direction).

padding-block: 20px; /* Top & Bottom */

📝 Shorthand & Longhand Syntax

Shorthand Syntax (Both sides equal)

padding-inline: 20px; padding-block: 15px;

Longhand Syntax (Different values)

padding-inline-start: 10px; /* Start of inline axis */ padding-inline-end: 20px; /* End of inline axis */ padding-block-start: 15px; /* Start of block axis (top) */ padding-block-end: 25px; /* End of block axis (bottom) */

Combined Shorthand

padding: 20px; /* All sides */ padding: 20px 30px; /* block inline */ padding: 20px 30px 25px 15px; /* top right bottom left */

Use Cases

  • Multilingual Sites: Works seamlessly with RTL languages (Arabic, Hebrew)
  • Responsive Design: More flexible than physical properties
  • Component Libraries: Create writing-direction agnostic components
  • Cards & Containers: Logical padding makes layouts more maintainable

💼 Real-World Examples

Example 1: Button

.button { padding-inline: 24px; padding-block: 12px; border: none; border-radius: 6px; background: #667eea; color: white; cursor: pointer; }

Example 2: Card Component

.card { padding-inline: 20px; padding-block: 16px; border-radius: 8px; box-shadow: 0 2px 8px rgba(0, 0, 0, 0.1); }

Example 3: Form Input

input, textarea { padding-inline: 12px; padding-block: 8px; border: 1px solid #ddd; border-radius: 4px; }

Example 4: Responsive with Logical Properties

.container { padding-inline: clamp(16px, 5vw, 40px); padding-block: clamp(20px, 8vh, 60px); } /* Scales padding based on viewport size */

⚡ Tips & Best Practices

✨ Benefit: Use logical properties for better i18n (internationalization) support without code changes
🎯 Consistency: Mix logical and physical properties cautiously—stick to one approach per project
🔍 Testing: Test your site in RTL mode to ensure logical properties work correctly
📱 Responsive: Combine with CSS custom properties (variables) for scalable spacing systems

Example: Spacing System with Variables

:root { --spacing-xs: 4px; --spacing-sm: 8px; --spacing-md: 16px; --spacing-lg: 24px; } .card { padding-inline: var(--spacing-lg); padding-block: var(--spacing-md); }

🔀 Logical vs Physical Properties

Physical Property Logical Property Advantage
padding-left / padding-right padding-inline-start / padding-inline-end Works with RTL languages automatically
padding-top / padding-bottom padding-block-start / padding-block-end Works with vertical writing modes
padding: 20px 30px; padding: 20px 30px; (same as physical) Shorthand is clearer with naming

CSS Display: Table

Complete Guide to CSS Table Display Properties

1. What is CSS Display: Table?

display: table is a CSS property that allows you to create table layouts without using actual HTML <table> elements. It applies CSS table formatting to any HTML element.

Key Concept:

You can convert any HTML element (div, section, article, etc.) into a table-like structure using CSS display properties. This provides:

  • Layout control without semantic HTML tables
  • Equal column heights automatically
  • Better separation between layout and structure
  • Flexible alignment options

Related Display Values:

  • display: table - Creates table container
  • display: table-row - Creates table row
  • display: table-cell - Creates table cell
  • display: table-header-group - Groups header rows
  • display: table-body - Groups body rows
  • display: table-footer-group - Groups footer rows
  • display: table-caption - Creates table caption
  • display: table-column - Defines column properties
  • display: table-column-group - Groups columns

Property Details:

display: table

The container element. Should wrap all rows and cells.

.container {
    display: table;
    width: 100%;
    border-collapse: collapse;
}

display: table-row

Creates horizontal rows within the table. All cells in a row have equal height.

.row {
    display: table-row;
    border-bottom: 1px solid #ddd;
}

display: table-cell

Creates individual cells. Automatically aligns vertically with other cells in same row.

.cell {
    display: table-cell;
    padding: 15px;
    vertical-align: middle;
}

10. table-layout Property

Controls how table cells are sized:

Two Values:

table-layout: auto (Default)

  • Column width is based on content
  • Cells expand/shrink to fit content
  • Slower rendering with large tables
  • More flexible column sizing

table-layout: fixed

  • Column width based on first row or specified widths
  • Faster rendering
  • Predictable column sizes
  • Content may overflow or truncate

Comparison:

/* Auto - flexible sizing */
.table-auto {
    display: table;
    table-layout: auto;  /* Default */
    width: 100%;
}

/* Fixed - rigid sizing */
.table-fixed {
    display: table;
    table-layout: fixed;
    width: 100%;
}
Use table-layout: fixed for:
  • Performance-critical applications
  • Tables with consistent column widths
  • Large datasets

11. border-collapse Property

Controls how borders are rendered in tables:

Two Values:

border-collapse: separate (Default)

Borders are rendered separately between cells.

.table {
    border-collapse: separate;
    border-spacing: 10px;  /* Space between cells */
}

border-collapse: collapse

Borders between adjacent cells are merged.

.table {
    border-collapse: collapse;  /* No space between borders */
}

Comparison Example:

border-collapse: separate
  • Allows border-spacing property
  • Each cell has its own border
  • Better for spaced layouts
border-collapse: collapse
  • Creates grid effect
  • More compact appearance
  • Traditional table look

12. Pros and Cons

Advantages:

  • Semantic HTML: Use div/section instead of <table>
  • Equal Heights: Cells in same row auto-equalize
  • Vertical Alignment: Easy centering with vertical-align
  • Flexible: Convert any element to table layout
  • No table semantics confusion: Better for non-tabular data
  • CSS-only: No HTML structure changes needed
  • Responsive-friendly: Easy to change layout with media queries

Disadvantages:

  • Accessibility: Screen readers may not recognize as table
  • Complex nesting: Requires specific HTML structure
  • Browser differences: Minor rendering variations
  • Column sizing: Can be tricky with dynamic content
  • Mobile-unfriendly: Needs media queries for responsiveness
  • Limited mobile support: Doesn't wrap well on small screens

14. Best Practices

✓ Do's:

  • Use display: table for layout, not tabular data
  • Add border-collapse: collapse for clean grids
  • Use table-layout: fixed for performance
  • Test accessibility with screen readers
  • Provide fallback styles for older browsers
  • Use meaningful HTML elements (div, section, article)
  • Combine with media queries for responsive design

✗ Don'ts:

  • Don't use for actual tabular data—use <table>
  • Don't forget accessibility attributes
  • Don't nest table displays too deeply
  • Don't use with complex animations
  • Don't ignore mobile responsiveness
  • Don't use for SEO-critical data
  • Don't hardcode column widths without flexibility

15. When to Use display: table

Good Use Cases:

  • Creating equal-height columns
  • Vertical centering without flexbox
  • Complex page layouts with sidebars
  • Card grids with consistent heights
  • Dashboard layouts
  • Feature comparison displays
  • Admin panel interfaces

When NOT to Use:

  • Actual tabular data (use <table>)
  • Modern layouts (use Flexbox or CSS Grid instead)
  • Simple layouts (Flexbox is simpler)
  • Responsive mobile designs
  • When accessibility is critical
  • SEO-sensitive content
Note: For modern projects, Flexbox or CSS Grid are usually better choices than display: table. Use table display when you specifically need table behavior like equal-height cells.

16. Making Tables Responsive

CSS Solution:

/* Desktop: Table layout */
@media (min-width: 768px) {
    .responsive-table {
        display: table;
        width: 100%;
    }
    
    .resp-row {
        display: table-row;
    }
    
    .resp-cell {
        display: table-cell;
        padding: 12px;
    }
}

/* Mobile: Block layout */
@media (max-width: 767px) {
    .responsive-table {
        display: block;
    }
    
    .responsive-header {
        display: none;  /* Hide header */
    }
    
    .resp-row {
        display: block;
        margin-bottom: 15px;
        border: 1px solid #ddd;
    }
    
    .resp-cell {
        display: block;
        padding: 10px;
    }
    
    .resp-cell::before {
        content: attr(data-label);
        font-weight: bold;
        display: block;
        margin-bottom: 5px;
    }
}
Tip: The table above uses this responsive technique. Resize your browser to see it in action!

    transition: background 0.3s ease;

.table-row:hover {
    background: #f0f4ff;

Technique 4: Responsive Grid Fallback

@supports (display: grid) {
    .layout {
        display: grid;
        grid-template-columns: 1fr 2fr 1fr;
    }
}

@supports not (display: grid) {
    .layout {
        display: table;
    }
}

20. Common Mistakes & Solutions

Mistake 1: Forgetting table-row

Problem: Cells appear in single row instead of multiple rows.

Solution: Always wrap cells in a display: table-row element.

Mistake 2: Wrong border-spacing

Problem: Borders appear twice thick between cells.

Solution: Use border-collapse: collapse to merge borders.

Mistake 3: vertical-align not working

Problem: Content not vertically centered.

Solution: Apply vertical-align only to display: table-cell elements.

Mistake 4: Unequal cell heights

Problem: Cells in same row have different heights.

Solution: Ensure all cells are direct children of same table-row.

Mistake 5: Poor mobile rendering

Problem: Table too wide on mobile devices.

Solution: Use media queries to change to block display on mobile.

⚠ Important: Test your tables across different screen sizes and browsers!

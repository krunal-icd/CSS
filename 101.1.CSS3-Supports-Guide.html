What is @supports?

The @supports rule is a CSS at-rule that allows you to apply styles conditionally based on browser support for specific CSS properties and values. It's the CSS equivalent of feature detection in JavaScript, enabling you to create progressive enhancement strategies that gracefully degrade in older browsers.

Core Concept:

  • Tests if the browser supports a specific CSS property and value combination
  • Applies styles only if the test condition is true
  • Enables progressive enhancement without JavaScript
  • Works with both standard and vendor-prefixed properties
  • Supports logical operators for complex conditions
Browser Support: All modern browsers (Chrome 28+, Firefox 22+, Safari 9+, Edge 12+). IE 11 does not support @supports.

Syntax & Structure

Basic Syntax

The fundamental structure of an @supports rule:

@supports (property: value) { /* Styles applied if property is supported */ selector { property: value; } }

Complete Example

@supports (display: grid) { .container { display: grid; grid-template-columns: repeat(3, 1fr); gap: 20px; } } @supports (display: flex) { .container { display: flex; justify-content: space-between; } }

Vendor-Prefixed Properties

@supports (display: -webkit-box) { .item { display: -webkit-box; -webkit-box-orient: vertical; } } @supports (-webkit-backdrop-filter: blur(10px)) { .blur-effect { -webkit-backdrop-filter: blur(10px); backdrop-filter: blur(10px); } }

Logical Operators

AND Operator

Test if multiple properties are supported (all conditions must be true):

@supports (display: grid) and (gap: 1rem) { .grid { display: grid; gap: 1rem; } } @supports (display: flex) and (justify-content: center) and (align-items: center) { .flex-center { display: flex; justify-content: center; align-items: center; } }

OR Operator

Test if at least one property is supported (any condition can be true):

@supports (display: grid) or (display: -ms-grid) { .layout { display: grid; } } @supports (backdrop-filter: blur(10px)) or (-webkit-backdrop-filter: blur(10px)) { .blur { backdrop-filter: blur(10px); } }

NOT Operator

Test if a property is NOT supported (condition must be false):

@supports not (display: grid) { .fallback-layout { display: flex; flex-wrap: wrap; } } @supports not (gap: 1rem) { .container > * + * { margin-left: 1rem; } }

Complex Combinations

Combine multiple operators with proper grouping:

@supports ((display: grid) and (gap: 1rem)) or (display: flex) { .modern-layout { display: grid; gap: 1rem; } } @supports (display: flex) and ((justify-content: space-between) or (justify-content: space-around)) { .flex-justify { display: flex; justify-content: space-between; } } @supports (display: grid) and not (display: -ms-grid) { .grid-modern { display: grid; grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); } }

Common Use Cases

CSS Grid Support

Use modern Grid layout when available, fallback to Flexbox:

@supports (display: grid) { .grid { display: grid; grid-template-columns: repeat(3, 1fr); } } @supports not (display: grid) { .grid { display: flex; flex-wrap: wrap; } }
Layout

Backdrop Filter

Apply glass morphism effects with vendor prefix detection:

@supports (backdrop-filter: blur(10px)) { .glass { backdrop-filter: blur(10px); } } @supports not (backdrop-filter: blur(10px)) and (-webkit-backdrop-filter: blur(10px)) { .glass { -webkit-backdrop-filter: blur(10px); } }
Effects

CSS Custom Properties

Detect CSS variables support for dynamic theming:

@supports (--css: variables) { :root { --primary: #667eea; --secondary: #764ba2; } button { background: var(--primary); } } @supports not (--css: variables) { button { background: #667eea; } }
Variables

Container Queries

Use container queries for responsive component behavior:

@supports (container-type: inline-size) { .card { container-type: inline-size; } @container (min-width: 400px) { .card { layout: optimized; } } }
Responsive

Aspect Ratio

Modern aspect ratio with fallback sizing:

@supports (aspect-ratio: 1) { .square { aspect-ratio: 1; width: 100%; } } @supports not (aspect-ratio: 1) { .square { width: 100%; padding-bottom: 100%; } }
Sizing

Sticky Positioning

Sticky headers with proper fallback:

@supports (position: sticky) { header { position: sticky; top: 0; z-index: 100; } } @supports not (position: sticky) { header { position: fixed; top: 0; width: 100%; } }
Positioning

Best Practices

✓ DO:

  • Test actual values: Use @supports (display: grid) not just @supports (display)
  • Provide fallbacks: Always include styles for unsupported browsers
  • Use with modern features: Grid, Flexbox, Custom Properties, Backdrop Filter
  • Group related rules: Keep progressive enhancement strategies together
  • Test vendor prefixes: Check for both prefixed and unprefixed versions
  • Combine with @media: Use @supports and @media queries together
  • Use logical operators: Create precise feature detection conditions

✗ DON'T:

  • Test unsupported syntax: @supports only works with valid CSS properties
  • Overuse @supports: Not needed for browsers that already have fallback support
  • Rely solely on @supports: Combine with proper progressive enhancement
  • Test JavaScript values: @supports is CSS-only, cannot detect JS features
  • Ignore browser compatibility: Remember IE 11 doesn't support @supports
  • Create overly complex conditions: Keep conditions readable and maintainable

Real-World Scenarios

Scenario 1: Progressive Grid Enhancement

Serve optimal layout based on browser capabilities:

/* Modern Grid Layout */ @supports (display: grid) and (grid-template-columns: subgrid) { .product-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 20px; } .product-item { display: grid; grid-template-columns: subgrid; } } /* Fallback to Basic Grid */ @supports (display: grid) and not (grid-template-columns: subgrid) { .product-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 20px; } } /* Legacy Flexbox */ @supports not (display: grid) { .product-grid { display: flex; flex-wrap: wrap; } .product-item { flex: 1 0 calc(25% - 20px); margin: 10px; } }

Scenario 2: Glass Morphism with Fallback

Modern glass effect with solid background fallback:

/* Solid fallback for older browsers */ .card { background: rgba(255, 255, 255, 0.9); border: 1px solid rgba(255, 255, 255, 0.5); } /* Enhanced glass effect */ @supports (backdrop-filter: blur(10px)) { .card { background: rgba(255, 255, 255, 0.6); backdrop-filter: blur(10px); border: 1px solid rgba(255, 255, 255, 0.7); } } /* Webkit prefix support */ @supports (-webkit-backdrop-filter: blur(10px)) and not (backdrop-filter: blur(10px)) { .card { -webkit-backdrop-filter: blur(10px); } }

Scenario 3: Dynamic Spacing with Gap Fallback

Modern gap property with manual margin fallback:

/* Fallback using margins */ .button-group > button + button { margin-left: 12px; } /* Modern gap-based spacing */ @supports (gap: 1rem) { .button-group { display: flex; gap: 12px; } .button-group > button + button { margin-left: 0; } }

Feature Detection Checklist

Feature @supports Test Priority Notes
CSS Grid (display: grid) High Major layout change, critical fallback needed
Flexbox (display: flex) High Well supported, minimal fallback needed
CSS Variables (--var: 0) Medium Dynamic theming, graceful degradation
Backdrop Filter (backdrop-filter: blur(1px)) Low Visual enhancement, not essential
Container Queries (container-type: inline-size) Medium Next-gen responsive, use with caution
Aspect Ratio (aspect-ratio: 1) Medium Prevents layout shift, important for images
Sticky Position (position: sticky) Low Enhancement, fixed position fallback works

Key Takeaways

  • Progressive Enhancement: @supports enables serving the best experience for each browser's capabilities
  • Graceful Degradation: Older browsers get functional, if less visually impressive, experiences
  • Three Logical Operators: Combine AND, OR, and NOT for complex feature detection
  • Test Actual Values: Include property values in tests, not just property names
  • Vendor Prefixes Matter: Test both prefixed and unprefixed versions for wider support
  • Works with All Selectors: @supports applies to any selector inside its rule
  • No JavaScript Required: Pure CSS feature detection without DOM manipulation
  • IE 11 Limitation: Remember that Internet Explorer 11 doesn't support @supports

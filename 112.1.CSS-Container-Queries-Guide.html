📦 CSS Container Queries

Component-Based Responsive Design

Style elements based on their container size, not viewport size

OVERVIEW What are Container Queries?

CSS Container Queries allow you to style elements based on the size of a parent container, rather than the viewport. It's component-based responsive design.

Key Concepts

  • Container Context: Define a container with container-type
  • Query Conditions: Use @container to style based on size
  • Component Independence: Components work at any size
  • Reusability: Same component adapts to different contexts

Problem It Solves

Media queries only respond to viewport size. What if a component is placed in a sidebar (narrow) vs main content (wide)? Container queries solve this:

  • Same component, different layouts — Adapt to parent container
  • Reusable components — Works in any context
  • Modular CSS — Style with component, not page
ℹ️ Revolutionary: Container queries represent a paradigm shift from viewport-based to component-based responsive design.

🔄 How Container Queries Work

Two steps: Define container, then query it.

Step 1: Define Container

.card-container {
  container-type: inline-size;
  container-name: card;
}

Step 2: Query Container

@container card (min-width: 400px) {
  .card-content {
    display: flex;
    flex-direction: row;
  }
}

Container-Type Values

  • inline-size: Query based on width (most common)
  • size: Query based on width and height
  • normal: No container (default)
✨ Best Practice: Use inline-size for most cases—it's more performant than size.

📝 Container Query Syntax

Query conditions work similar to media queries.

Breakdown: @container queries

Basic Syntax: @container container-name (condition) { /* styles */ }
Width Query: @container (min-width: 400px) { /* ... */ }

Query unnamed container by condition

Named Container Query: @container card (min-width: 400px) { /* ... */ }

Query specific named container

Multiple Conditions: @container (min-width: 400px) and (min-height: 300px) { /* ... */ }

Combine multiple conditions with and

Common Query Conditions

  • min-width: Container width ≥ value
  • max-width: Container width ≤ value
  • min-height: Container height ≥ value
  • max-height: Container height ≤ value
  • aspect-ratio: Container aspect ratio

🔄 Media Queries vs Container Queries

Aspect Media Queries Container Queries
Responds to Viewport size Container size
Scope Page-wide Component-level
Reusability Limited Excellent
Location-dependent No Yes (context-aware)
Syntax @media (condition) @container (condition)
Browser Support 99%+ 75%+ (improving)
ℹ️ Complementary: Media queries and container queries work together. Use both for optimal responsive design.

🎨 Practical Examples

Example 1: Responsive Card Component

Card that adapts to container width

/* Define container */
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

/* Mobile layout (small container) */
.card-content {
  display: flex;
  flex-direction: column;
}

/* Desktop layout (large container) */
@container card (min-width: 500px) {
  .card-content {
    flex-direction: row;
  }
}

Example 2: Sidebar Component

Component works in both sidebar and main content

/* Same component, different layouts */
.component {
  container-type: inline-size;
}

h2 { font-size: 1.2em; }
p { display: none; }

@container (min-width: 300px) {
  h2 { font-size: 1.5em; }
  p { display: block; }
}

Example 3: Image Grid with Aspect Ratio

Grid adapts based on container width

.gallery {
  container-type: inline-size;
  display: grid;
  grid-template-columns: 1fr;
}

@container (min-width: 600px) {
  .gallery {
    grid-template-columns: repeat(2, 1fr);
  }
}

@container (min-width: 1000px) {
  .gallery {
    grid-template-columns: repeat(3, 1fr);
  }
}

🔧 Container Query Properties

container-type inline-size | size | normal

Defines what dimension(s) to query. inline-size for width, size for both dimensions.

container-name identifier | none

Optional name to target specific containers in @container queries. Useful with nested containers.

container shorthand

Shorthand for both type and name: container: card / inline-size;

@container query rule

At-rule for applying conditional styles based on container dimensions.

⚡ Advanced Techniques

Technique 1: Nested Containers with Names

.outer {
  container: outer / inline-size;
}

.inner {
  container: inner / inline-size;
}

@container outer (min-width: 600px) { /* targets outer */ }
@container inner (min-width: 300px) { /* targets inner */ }

Technique 2: Combining with Media Queries

/* Combine both for optimal responsiveness */
@container (min-width: 400px) {
  .content { flex-direction: row; }
}

@media (max-width: 600px) {
  .sidebar { display: none; }
}

Technique 3: Container Query Units

.responsive-font {
  font-size: 1cqw; /* 1% container width */
  padding: 2cqmin; /* 2% of smaller dimension */
  width: 90cqw; /* 90% of container width */
}

Technique 4: Container Query with Aspect Ratio

@container card (
  min-width: 400px
  and aspect-ratio: 2 / 1
) {
  .card-image {
    width: 40%;
  }
}

🏆 Best Practices & Tips

✅ Do:

  • Use for components: Perfect for reusable widgets
  • Name containers: For clarity in complex layouts
  • Use inline-size primarily: Better performance than size
  • Combine with media queries: For optimal control
  • Test at different sizes: Verify breakpoints work
  • Start simple: Begin with basic min-width queries

❌ Don't:

  • Replace all media queries: Keep both for balance
  • Forget container-type: Required to query
  • Overuse aspect-ratio queries: Can be limiting
  • Ignore browser support: Check target browsers
  • Use size carelessly: Causes layout thrashing
  • Nest unnecessarily: Keep hierarchy simple
⚠️ Performance Note: The size container-type can impact performance. Use inline-size when possible. Only use size when you really need both dimensions.

⚠️ Common Issues & Solutions

Issue 1: Container Query Not Working

Problem: @container styles aren't applying.

Solution: Verify container-type is set on parent

/* ❌ Won't work */
@container (min-width: 400px) { /* No container defined */ }

/* ✅ Works */
.parent { container-type: inline-size; }
@container (min-width: 400px) { /* Queries parent */ }

Issue 2: Infinite Loop / Layout Thrashing

Problem: Container size changes cause layout shifts.

Solution: Avoid width-affecting properties in @container

/* ❌ Can cause loop */
@container (min-width: 400px) {
  .element { width: 500px; }
}

/* ✅ Safe */
@container (min-width: 400px) {
  .element { font-size: 1.5em; }
}

Issue 3: Container Name Not Found

Problem: Query targets non-existent container name.

Solution: Use correct container name or omit for unnamed query

/* ❌ Wrong name */
.parent { container-name: card; }
@container product { /* card !== product */ }

/* ✅ Correct */
.parent { container-name: card; }
@container card { /* matches */ }

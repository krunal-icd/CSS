📚 HTML Details & Summary Tags Tutorial

📖 Introduction

The <details> and <summary> elements are semantic HTML tags used to create expandable/collapsible content. The <summary> serves as the clickable header, while <details> is the container.

💡 Native Solution: No JavaScript required for basic expand/collapse functionality—these tags handle it automatically!

Basic Structure

<details>
  <summary>Click to expand</summary>
  <p>This content is hidden by default</p>
</details>

Basic Details & Summary

🔍 What is this?

The <details> element creates a disclosure widget in which information is visible only when the widget is toggled into an "open" state. A summary or legend can be provided using the <summary> element.

🎛️ Attributes & Methods

The open Attribute

The open attribute determines whether details are visible by default.

<!-- Closed by default -->
<details>
  <summary>Details</summary>
  <p>Content</p>
</details>

<!-- Open by default -->
<details open>
  <summary>Details</summary>
  <p>Content</p>
</details>

JavaScript API

Property/Method Description Example
.open Boolean - whether details are open if (details.open) { ... }
toggle event Fires when details open/close details.addEventListener('toggle', ...)

❓ FAQ Example

Here's a practical FAQ section using details and summary:

What is the difference between details and accordion? ▼

Details elements can all be open at the same time, while accordion components typically only allow one section open at a time. Accordions require JavaScript to manage the mutual exclusivity.

Can I nest details elements? ▼

Yes! You can nest details elements inside other details elements. This is useful for creating hierarchical content structures like file trees or nested menus.

Is browser support good? ▼

Yes! Details and summary are supported in all modern browsers (Chrome, Firefox, Safari, Edge). Internet Explorer has no support, so consider a polyfill if you need to support older browsers.

⚡ Best Practices

Do's ✅

  • Use <summary> inside <details> for semantic structure
  • Keep summary text concise and descriptive
  • Use for non-critical or supplementary information
  • Style to indicate interactivity (cursor: pointer)
  • Test nested details functionality
  • Provide clear visual feedback on state change

Don'ts ❌

  • Don't use for primary content users must see
  • Don't nest details too deeply (hard to navigate)
  • Don't remove the visual indicator without replacement
  • Don't use multiple summaries in one details element
  • Don't hide important form fields in details
  • Don't forget accessibility (keyboard navigation works by default)

🔄 Details vs Accordion

Details & Summary

  • Native HTML element
  • Multiple sections can be open
  • No JavaScript required
  • Smaller file size
  • Built-in accessibility
  • Limited styling options

Accordion (JavaScript)

  • Custom implementation
  • Only one section open at a time
  • Requires JavaScript
  • More control and customization
  • Needs manual ARIA attributes
  • Highly customizable styling

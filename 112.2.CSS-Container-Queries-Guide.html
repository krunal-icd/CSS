Component Reusability

When to Use Container Queries:

  • Reusable card components: Cards that work in any width context
  • Widget libraries: Widgets that adapt to their container
  • Dashboard layouts: Components that resize with grid cells
  • Sidebar content: Sidebars with responsive sub-components
  • Grid galleries: Images/items that adapt to column width
  • Modular design systems: Components that work anywhere

Best Practices:

  • Use container-type: inline-size: Most common and performant option
  • Name your containers: Makes complex layouts clearer
  • Test at different sizes: Resize containers to verify breakpoints
  • Combine with media queries: Use both for optimal responsive design
  • Start with simple queries: Begin with min-width before complex rules
  • Keep breakpoints logical: Use meaningful size thresholds
💡 Pro Tip: Container queries make components truly reusable. The same component adapts perfectly whether it's in a wide main content area or a narrow sidebar—no media query duplication needed!

⚡ Quick Implementation Guide

Step 1: Define Container

.component-wrapper { container-type: inline-size; container-name: component; }

Step 2: Write Container Queries

@container component (min-width: 400px) { .component-content { display: flex; flex-direction: row; } }

Step 3: Add More Breakpoints

@container component (min-width: 600px) { .component-content { gap: 30px; } }
✨ Done! Your component now adapts to its container size, making it reusable anywhere in your application.

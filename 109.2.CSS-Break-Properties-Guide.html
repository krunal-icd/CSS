CSS Implementation:

h1, h2 {
  break-before: always; /* New page for chapters */
  break-after: avoid; /* Keep with content */
  page-break-before: always; /* Legacy */
  page-break-after: avoid; /* Legacy */
}

h1:first-child {
  break-before: auto; /* First chapter on page 1 */
}
✨ Result: Each chapter starts on a new page automatically, with headings never separated from content.

@media print {

When to Use Each Property:

break-before: always

Use for chapter headings, major sections, or new content that should start fresh on a new page or column.

break-after: avoid

Use on headings to keep them with their content, preventing orphaned titles at bottom of pages.

break-inside: avoid

Use on cards, tables, and cohesive blocks to prevent them from being split across pages or columns.

Best Practices Summary:

  • Always include legacy page-break properties for backward compatibility (page-break-before, page-break-inside, etc.)
  • Test in both print and multi-column contexts as break properties work in both scenarios
  • Use break-inside: avoid conservatively on critical elements like cards and tables
  • Avoid excessive break-before: always which can create unwanted whitespace
  • Print preview before deployment to ensure breaks work as expected
  • Combine with other properties like orphans/widows for professional documents
⚠️ Important: Test break properties by actually printing the page or using Print Preview (Ctrl+P in Chrome, Ctrl+Shift+P in Firefox). Different browsers may handle breaks slightly differently!

For Print Documents:

  • ☐ Use @media print context
  • ☐ Add break-before: always on chapters
  • ☐ Apply break-inside: avoid to tables
  • ☐ Test in print preview

General Best Practices:

  • ☐ Avoid conflicting break rules
  • ☐ Test in multiple browsers

Performance Tips:

  • ☐ Minimize number of break points
  • ☐ Avoid nested break properties

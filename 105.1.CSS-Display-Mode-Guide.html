CSS Display-Mode @media Rule

Complete Guide to Progressive Web App Display Modes

1. What is display-mode?

The display-mode CSS media query allows you to apply different styles based on how your web app is displayed. This is primarily used for Progressive Web Apps (PWAs) that can be installed on devices.

Key Characteristics:

  • Detects how the app is launched (browser, standalone, fullscreen, etc.)
  • Only works with Progressive Web Apps (PWAs)
  • Requires a valid Web App Manifest file
  • Enables optimized UI for different display contexts
  • Works alongside other media queries
  • Essential for responsive PWA design

Syntax:

@media (display-mode: browser) {
    /* Styles when opened in browser */
}

@media (display-mode: standalone) {
    /* Styles when installed as PWA */
}

@media (display-mode: fullscreen) {
    /* Styles in fullscreen mode */
}

@media (display-mode: minimal-ui) {
    /* Styles with minimal browser UI */
}

2. Display Mode Values

There are four main display modes available for PWAs:

🌐 browser

Default mode

Opens in regular browser window with full UI (address bar, navigation buttons, etc.)

✨ standalone

Most common PWA mode

Looks and feels like a native app. No browser UI visible.

🖥️ fullscreen

Immersive mode

Uses all available screen space. No system UI visible.

🎯 minimal-ui

Limited browser UI

Minimal browser UI elements. Only essential controls visible.

Detailed Descriptions:

1. browser

@media (display-mode: browser) {
    /* Optimize for browser context */
    body {
        padding-top: 20px; /* Space for browser UI */
    }
    
    .browser-nav {
        display: block;
    }
}

2. standalone

@media (display-mode: standalone) {
    /* PWA installed on device */
    body {
        padding-top: 0; /* Use full space */
    }
    
    .app-header {
        display: flex;
        justify-content: space-between;
        align-items: center;
    }
}

3. fullscreen

@media (display-mode: fullscreen) {
    /* Maximum immersion */
    body {
        margin: 0;
        padding: 0;
        width: 100vw;
        height: 100vh;
    }
    
    .status-bar {
        display: none;
    }
}

4. minimal-ui

@media (display-mode: minimal-ui) {
    /* Minimal browser controls */
    body {
        padding: 0; /* Full space available */
    }
}

3. Web App Manifest Configuration

To use display-mode media queries, you need a valid Web App Manifest file:

manifest.json Example:

{
  "name": "My Awesome App",
  "short_name": "MyApp",
  "description": "A progressive web app",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#667eea",
  "orientation": "portrait-primary",
  "icons": [
    {
      "src": "/icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    },
    {
      "src": "/icon-512.png",
      "sizes": "512x512",
      "type": "image/png"
    }
  ]
}

HTML Link to Manifest:

<link rel="manifest" href="/manifest.json">

Display Mode Options in Manifest:

Value Description Fallback
browser Open in browser tab Opens as browser tab
standalone Like native app Falls back to browser
fullscreen Fullscreen immersive Falls back to standalone
minimal-ui Minimal browser UI Falls back to standalone
Important: The manifest.json "display" property determines which mode is used by default. The CSS media query detects and responds to the actual mode.

4. Practical Implementation Examples

Example 1: Header Responsive to Display Mode

/* Browser: Show full header with navigation */
@media (display-mode: browser) {
    .app-header {
        height: 64px;
        display: flex;
        justify-content: space-between;
        align-items: center;
        border-bottom: 1px solid #ddd;
    }
    
    .app-nav {
        display: flex;
        gap: 20px;
    }
}

/* Standalone: Optimize for app-like feel */
@media (display-mode: standalone) {
    .app-header {
        height: 56px;
        background: #667eea;
        color: white;
        position: fixed;
        top: 0;
        left: 0;
        right: 0;
        z-index: 100;
    }
    
    .app-nav {
        display: none; /* Hide browser nav, use app nav */
    }
    
    body {
        padding-top: 56px;
    }
}

Example 2: Status Bar Visibility

/* Show status info in browser mode */
@media (display-mode: browser) {
    .status-bar {
        display: block;
        padding: 10px;
        background: #f5f5f5;
        border-bottom: 1px solid #ddd;
        font-size: 0.9em;
        color: #666;
    }
}

/* Hide status bar in installed app */
@media (display-mode: standalone) {
    .status-bar {
        display: none;
    }
}

Example 3: Safe Area Handling

/* Account for notches and safe areas in fullscreen */
@media (display-mode: fullscreen) {
    body {
        padding-top: max(0px, env(safe-area-inset-top));
        padding-left: max(0px, env(safe-area-inset-left));
        padding-right: max(0px, env(safe-area-inset-right));
        padding-bottom: max(0px, env(safe-area-inset-bottom));
    }
}

Example 4: Bottom Navigation for Standalone

/* Browser: Standard layout */
@media (display-mode: browser) {
    .bottom-nav {
        display: none;
    }
}

/* Standalone: Use bottom navigation like native apps */
@media (display-mode: standalone) {
    .bottom-nav {
        display: flex;
        position: fixed;
        bottom: 0;
        left: 0;
        right: 0;
        height: 56px;
        border-top: 1px solid #ddd;
        background: white;
    }
    
    main {
        padding-bottom: 56px;
    }
}

5. Combining with Other Media Queries

Display Mode + Screen Size:

/* Standalone on desktop */
@media (display-mode: standalone) and (min-width: 1024px) {
    .sidebar {
        display: flex;
        width: 250px;
    }
    
    main {
        margin-left: 250px;
    }
}

/* Standalone on mobile */
@media (display-mode: standalone) and (max-width: 768px) {
    .sidebar {
        display: none;
    }
    
    main {
        width: 100%;
    }
}

Display Mode + Orientation:

/* Fullscreen portrait */
@media (display-mode: fullscreen) and (orientation: portrait) {
    body {
        height: 100vh;
    }
}

/* Fullscreen landscape */
@media (display-mode: fullscreen) and (orientation: landscape) {
    .header {
        height: 40px;
    }
}

Display Mode + Color Scheme:

/* Standalone dark mode */
@media (display-mode: standalone) and (prefers-color-scheme: dark) {
    body {
        background: #1a1a1a;
        color: #e0e0e0;
    }
    
    .app-header {
        background: #000;
    }
}

Display Mode + Hover:

/* Hover available in browser, not on touch device standalone */
@media (display-mode: browser) and (hover: hover) {
    button {
        cursor: pointer;
    }
    
    button:hover {
        background: #f0f0f0;
    }
}

/* Touch device in standalone mode */
@media (display-mode: standalone) and (hover: none) {
    button {
        padding: 16px; /* Larger touch targets */
    }
}

8. Responsive Layout Patterns

Pattern 1: Top Navigation + Content

/* Browser mode: Traditional layout */
@media (display-mode: browser) {
    body {
        display: grid;
        grid-template-rows: auto 1fr;
    }
    
    .header {
        position: static;
        height: auto;
    }
    
    main {
        padding: 20px;
    }
}

/* Standalone: App-like layout */
@media (display-mode: standalone) {
    body {
        display: grid;
        grid-template-rows: auto 1fr auto;
    }
    
    .header {
        position: fixed;
        top: 0;
        left: 0;
        right: 0;
        z-index: 100;
        height: 56px;
    }

        padding-top: 56px;
        padding-bottom: 56px;
    }
    
    .nav-bottom {
        position: fixed;
        bottom: 0;
        left: 0;
        right: 0;
        height: 56px;
    }
}

Pattern 2: Sidebar + Content

/* Browser: Sidebar always visible on desktop */
@media (display-mode: browser) and (min-width: 1024px) {
    body {
        display: grid;
        grid-template-columns: 250px 1fr;
    }
    
    .sidebar {
        display: block;
        border-right: 1px solid #ddd;
    }
}

/* Standalone: Hamburger menu on mobile */
@media (display-mode: standalone) and (max-width: 768px) {
    body {
        display: grid;
        grid-template-rows: auto 1fr;
    }
    
    .sidebar {
        display: none;
    }
    
    .menu-toggle {
        display: block;
    }
}

Pattern 3: Modal & Overlay Handling

/* Adjust for safe areas in fullscreen */
@media (display-mode: fullscreen) {
    .modal {
        padding: env(safe-area-inset-top) 
                 env(safe-area-inset-right) 
                 env(safe-area-inset-bottom) 
                 env(safe-area-inset-left);
    }
}

9. Best Practices

✓ Do's:

  • Always include a fallback for browser mode
  • Use standalone as primary PWA mode
  • Test on actual devices and emulators
  • Combine with other media queries for responsive design
  • Account for notches with safe-area-inset
  • Provide appropriate touch targets in app mode
  • Use persistent navigation for standalone apps
  • Hide browser-specific UI elements in app mode

✗ Don'ts:

  • Don't assume all devices support all display modes
  • Don't hide essential navigation in standalone mode
  • Don't use fullscreen carelessly - respect user expectations
  • Don't ignore safe areas on notched devices
  • Don't make touch targets too small in app mode
  • Don't rely solely on display-mode for layout decisions
  • Don't forget to test responsiveness

10. Testing & Debugging

Chrome DevTools Method:

  1. Open DevTools (F12)
  2. Click the three dots menu → More tools → Rendering
  3. Find "Emulate CSS media feature prefers-color-scheme" dropdown
  4. Scroll to find display-mode simulator (if available)
  5. Or use Command Palette (Ctrl+Shift+P) and search for display-mode

Firefox Method:

  1. Open DevTools (F12)
  2. Go to Inspector
  3. Click the "Responsive Design Mode" button (Ctrl+Shift+M)
  4. Use the settings to simulate PWA display modes

JavaScript Detection:

// Check current display mode
if (window.matchMedia('(display-mode: standalone)').matches) {
    console.log('Running as standalone PWA');
}

if (window.matchMedia('(display-mode: fullscreen)').matches) {
    console.log('Running in fullscreen mode');
}

// Listen for display mode changes
window.matchMedia('(display-mode: standalone)').addEventListener('change', (e) => {
    if (e.matches) {
        console.log('Switched to standalone mode');
    }
});

Debug Display Mode:

const displayMode = (() => {
    if (window.matchMedia('(display-mode: fullscreen)').matches) {
        return 'fullscreen';
    }
    if (window.matchMedia('(display-mode: standalone)').matches) {
        return 'standalone';
    }
    if (window.matchMedia('(display-mode: minimal-ui)').matches) {
        return 'minimal-ui';
    }
    return 'browser';
})();

console.log('Display mode:', displayMode);

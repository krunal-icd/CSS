CSS Animation-Fill-Mode Property

Complete Guide to Element State Before and After Animations

What is Animation-Fill-Mode?

The animation-fill-mode property specifies how a CSS animation applies styles to its target element before and after the animation runs. It controls whether the element returns to its original state or maintains the styles from the animation keyframes.

Key Purpose: Animation-fill-mode determines if your animated element "sticks" to its final state or "resets" after animation completes. This is crucial for creating polished UI interactions.

Without animation-fill-mode, elements often "snap" back to their original state, creating an unpolished appearance. With it, you can control exactly how the element should behave.

Syntax & Property Values

Basic Syntax

animation-fill-mode: none | forwards | backwards | both;

All Animation-Fill-Mode Values

Value Before Animation After Animation Use Case
none Original state Original state Animation loops infinitely
forwards Original state Final keyframe (100%) Keep final animation state
backwards First keyframe (0%) Original state Start from animation first frame
both First keyframe (0%) Final keyframe (100%) Full animation state handling

Understanding Each Fill-Mode Value

1. animation-fill-mode: none (Default)

Timeline: none

What it does: The element stays in its original CSS state before the animation starts. After the animation completes, it immediately returns to the original state.

When to use:

  • Infinite animations (loops continuously)
  • Temporary visual effects like hover animations
  • Interactive feedback that shouldn't persist

Example:

div { animation: spin 2s linear infinite; animation-fill-mode: none; /* Default */ } @keyframes spin { 0% { transform: rotate(0deg); } 100% { transform: rotate(360deg); } }

2. animation-fill-mode: forwards

Timeline: forwards

Final State

What it does: The element stays in its original state before the animation. After the animation finishes, it remains in the final keyframe state (100%).

When to use:

  • Showing information after animation completes
  • Dropdown menus expanding and staying open
  • Elements sliding into place and staying there
  • Most common fill-mode for one-time animations

Example: Slide-in Navigation

.nav-menu { transform: translateX(-100%); animation: slideIn 0.5s ease-out 1; animation-fill-mode: forwards; /* Menu stays visible after animation */ } @keyframes slideIn { 0% { transform: translateX(-100%); } 100% { transform: translateX(0); } }

What it does: The element immediately applies the first keyframe state (0%) when defined, even during the delay period. After animation completes, it returns to the original state.

When to use:

  • Setting up initial animation state before delay ends
  • Page load animations with delays
  • Preparing element for animation visibility
  • Avoiding "jump" effects during animation startup

Example: Fade In on Page Load

.content { opacity: 0; animation: fadeIn 0.6s ease-in; animation-delay: 0.3s; animation-fill-mode: backwards; } @keyframes fadeIn { 0% { opacity: 0; } 100% { opacity: 1; } }

What it does: Combines backwards and forwards. Applies the first keyframe before animation and remains in the final keyframe state after.

When to use:

  • Maximum control over element state at all times
  • Complex animations requiring full state management
  • Multi-step sequential animations
  • Critical user interactions where precision matters

Example: Modal Opening Animation

.modal { opacity: 0; transform: scale(0.8); animation: modalOpen 0.4s ease-out 0.2s; animation-fill-mode: both; /* Modal appears after delay and stays visible */ } @keyframes modalOpen { 0% { opacity: 0; transform: scale(0.8); } 100% { opacity: 1; transform: scale(1); } }

Side-by-Side Comparison

Use forwards for:

  • ✓ Slide-in menus
  • ✓ Reveal animations
  • ✓ Open overlays
  • ✓ Show/hide transitions
  • ✓ Single animations
  • ✓ Most common choice

Use both for:

  • ✓ Complex multi-step
  • ✓ Delayed animations
  • ✓ Modal dialogs
  • ✓ Full state control
  • ✓ Choreographed sequences
  • ✓ Maximum precision

Use backwards for:

  • ✓ Hiding initial state
  • ✓ With animation-delay
  • ✓ Zero initial opacity
  • ✓ Page load effects
  • ✓ Preventing jumps
  • ✓ Less common

Use none for:

  • ✓ Infinite loops
  • ✓ Spinners/loaders
  • ✓ Pulse effects
  • ✓ Background animations
  • ✓ Default behavior OK
  • ✓ Most common with infinite

Real-World Practical Examples

Example 1: Button Click Feedback (forwards)

Use Case: Button scales and remains slightly enlarged briefly.

button { padding: 10px 20px; transition: transform 0.2s; } button:active { animation: buttonPress 0.3s ease-out 1 forwards; } @keyframes buttonPress { 0% { transform: scale(1); } 100% { transform: scale(1.05); } }

Example 2: Page Content Reveal (both)

Use Case: Content fades in from top with delay and stays visible.

.page-content { opacity: 0; transform: translateY(20px); animation: contentReveal 0.6s ease-out 0.3s 1 both; } @keyframes contentReveal { 0% { opacity: 0; transform: translateY(20px); } 100% { opacity: 1; transform: translateY(0); } }

Example 3: Infinite Loading Spinner (none)

Use Case: Spinner rotates infinitely and never stops.

.spinner { width: 50px; height: 50px; border: 5px solid #f3f3f3; border-top: 5px solid #667eea; border-radius: 50%; animation: spin 1s linear infinite none; } @keyframes spin { 0% { transform: rotate(0deg); } 100% { transform: rotate(360deg); } }

Example 4: Modal Entrance (backwards)

Use Case: Modal hidden initially during delay, then visible after entering from animation.

.modal-overlay { opacity: 0; animation: fadeIn 0.3s ease 1 backwards; } .modal { transform: scale(0.9); animation: scaleIn 0.4s ease 0.15s 1 backwards; } @keyframes fadeIn { 0% { opacity: 0; } 100% { opacity: 1; } } @keyframes scaleIn { 0% { transform: scale(0.9); } 100% { transform: scale(1); } }

Animation-Fill-Mode + Animation-Delay

The interaction between animation-fill-mode and animation-delay is crucial for understanding behavior:

Timeline with Animation-Delay

Phase 1: Delay Period (before animation starts)
  • none: Original CSS state
  • forwards: Original CSS state
  • backwards: First @keyframe (0%) state
  • both: First @keyframe (0%) state
Phase 2: Animation Running (during duration)
  • All values: Element animates through @keyframes
Phase 3: After Animation (when completed)
  • none: Back to original CSS state
  • forwards: Stays in final @keyframe (100%) state
  • backwards: Back to original CSS state
  • both: Stays in final @keyframe (100%) state

Example: Staggered List Animation

.list-item { opacity: 0; animation: fadeIn 0.5s ease-out 1 forwards; } /* Each item staggered by 0.1s */ .list-item:nth-child(1) { animation-delay: 0s; } .list-item:nth-child(2) { animation-delay: 0.1s; } .list-item:nth-child(3) { animation-delay: 0.2s; } .list-item:nth-child(4) { animation-delay: 0.3s; } @keyframes fadeIn { 0% { opacity: 0; transform: translateY(10px); } 100% { opacity: 1; transform: translateY(0); } }
Pro Tip: Use forwards with animation-delay for sequential reveals. The delay won't cause unwanted "snapping" because fill-mode keeps the final state.

Best Practices & Tips

✓ Best Practices:
  • Default to forwards for most one-time animations
  • Use none for infinite/looping animations
  • Use both when you need precise control with delays
  • Test with animation-delay to verify behavior
  • Consider using animation-fill-mode in animation shorthand
  • Document your choice for team clarity
⚠ Common Mistakes:
  • Forgetting fill-mode, element "snaps" back unexpectedly
  • Using forwards with infinite animations (no effect)
  • Not testing with animation-delay
  • Wrong fill-mode causing janky transitions
  • Mixing fill-mode values between related animations

Animation Shorthand Property

You can include fill-mode in the animation shorthand:

animation: name duration timing-function delay iteration-count direction fill-mode play-state;

Examples:

/* Full shorthand */ .element { animation: slideIn 0.5s ease-out 0 1 normal forwards running; } /* Without optional properties */ .element { animation: slideIn 0.5s ease-out 0 1 forwards; } /* Minimal (using defaults) */ .element { animation: slideIn 0.5s forwards; }

Conclusion

Animation-fill-mode is essential for controlling how CSS animations integrate with your page layout and interactivity. By choosing the right value, you create polished, professional animations that feel intentional rather than disruptive.

Quick Decision Guide:

  • One-time animations: Use forwards
  • Infinite animations: Use none
  • With delays: Use both for precision
  • Complex sequences: Use both for control
  • Hover effects: Use none (reset on hover end)

CSS Attribute Selectors

Complete Guide to Selecting Elements by Attributes

CSS Attribute Selectors allow you to target HTML elements based on the presence or value of their attributes. They enable precise, flexible element selection without requiring additional classes or IDs. Attribute selectors are powerful for form styling, data attributes, and matching partial values.

Overview of Attribute Selectors

CSS provides eight types of attribute selectors, each serving different selection needs:

[attr] - Presence

What It Does

Selects any element that has the specified attribute, regardless of its value.

Syntax

[attributeName] {
  property: value;
}

Example

HTML:

<button>Active</button>
<button disabled>Disabled</button>
<button disabled>Also Disabled</button>

CSS:

/* Selects any button with disabled attribute */
button[disabled] {
  opacity: 0.5;
  cursor: not-allowed;
}

Result: Both disabled buttons are styled, regardless of disabled value.

Why Use Presence Selector?

Common Use Cases

  • Styling disabled form elements
  • Styling form elements with required attribute
  • Targeting elements with data attributes
  • Styling elements with aria attributes
  • Selecting elements with any title attribute
[attr=value] - Exact Match

What It Does

Selects elements where the attribute equals the value exactly. This is case-sensitive.

Syntax

[attributeName="value"] {
  property: value;
}

Example

HTML:

<input type="text" placeholder="Name">
<input type="email" placeholder="Email">
<input type="submit" value="Submit">

CSS:

/* Only submit buttons */
input[type="submit"] {
  background: #667eea;
  color: white;
  cursor: pointer;
}

Result: Only the submit input is styled.

Why Use Exact Match?

Common Use Cases

  • Styling specific input types
  • Targeting elements with specific data attribute values
  • CSS-based state management
  • Different styling for different link types
  • Attribute-based conditional styling
[attr~=value] - Word Match

What It Does

Selects elements where the attribute contains the value as a space-separated word. Perfect for class attributes!

Syntax

[attributeName~="value"] {
  property: value;
}

Example

HTML:

<div class="button primary">Primary</div>
<div class="button secondary">Secondary</div>
<div class="button-large">Large</div>

CSS:

/* Matches class~="button" (word match) */
[class~="button"] {
  display: inline-block;
  padding: 10px 15px;
}

/* Note: .button-large NOT matched (not a word) */

Result: First two divs matched (button is a word). Third not matched (button-large is one word).

Why Use Word Match?

Common Use Cases

  • Selecting elements with a class without using .class notation
  • Matching space-separated attribute values
  • Data attribute with multiple space-separated values
  • Styling based on role attributes with multiple values
[attr|=value] - Prefix Match

What It Does

Selects elements where the attribute starts with value followed by a hyphen, or equals value exactly. Commonly used for language codes.

Syntax

[attributeName|="value"] {
  property: value;
}

Example

HTML:

<div lang="en">English</div>
<div lang="en-US">US English</div>
<div lang="en-GB">British English</div>
<div lang="fr">French</div>

CSS:

/* Matches lang="en" or lang="en-*" */
[lang|="en"] {
  font-style: italic;
}

Result: First three divs matched (en, en-US, en-GB). French not matched.

Why Use Prefix Match?

Common Use Cases

  • Language attribute targeting (lang="en-*")
  • BEM-like naming conventions
  • Semantic versioning in data attributes
  • Country/region code matching
[attr^=value] - Starts With

What It Does

Selects elements where the attribute starts with the value. No hyphen required.

Syntax

[attributeName^="value"] {
  property: value;
}

Example

HTML:

<a href="https://example.com">Secure Link</a>
<a href="http://example.com">Regular Link</a>
<a href="/local">Local Link</a>

CSS:

/* Only HTTPS links */
a[href^="https"] {
  color: green;
}

/* External links */
a[href^="http"] {
  text-decoration: underline;
}

Result: First link is green. First two are underlined.

Why Use Starts With?

Common Use Cases

  • Styling external vs internal links (http/https vs /)
  • Differentiating link types by protocol
  • Data attribute prefix matching
  • Icon selection based on URL patterns
[attr$=value] - Ends With

What It Does

Selects elements where the attribute ends with the value.

Syntax

[attributeName$="value"] {
  property: value;
}

Example

HTML:

<img src="image.png" alt="Photo">
<img src="image.jpg" alt="Photo">
<img src="image.svg" alt="Icon">

CSS:

/* PNG images */
img[src$=".png"] {
  border: 2px solid #667eea;
}

/* SVG images */
img[src$=".svg"] {
  filter: drop-shadow(0 0 2px);
}

Result: PNG image has blue border. SVG has drop shadow.

Why Use Ends With?

Common Use Cases

  • File type detection (.png, .jpg, .pdf, .doc)
  • Link target detection (#section, ?query)
  • Email domain matching
  • URL extension-based styling
  • Dynamic icon assignment based on file type
[attr*=value] - Contains

What It Does

Selects elements where the attribute contains the value anywhere.

Syntax

[attributeName*="value"] {
  property: value;
}

Example

HTML:

<input name="user_name" placeholder="Username">
<input name="user_email" placeholder="Email">
<input name="admin_id" placeholder="ID">

CSS:

/* Any input with "user" in name */
input[name*="user"] {
  border: 2px solid #667eea;
}

Result: First two inputs have blue border (both contain "user").

Why Use Contains?

Common Use Cases

  • Matching form inputs by name pattern
  • Data attribute pattern matching
  • Finding elements with partial class matches
  • URL parameter detection
  • Error/warning message styling
[attr operator i] - Case Insensitive

What It Does

Add the i flag to any attribute selector to make matching case-insensitive.

Syntax

[attributeName="value" i] {
  property: value;
}

Example

HTML:

<input type="text">
<input type="TEXT">
<input type="Text">

CSS:

/* Case sensitive - only matches "text" */
input[type="text"] {
  border: 1px solid red;
}

/* Case insensitive - matches all variations */
input[type="text" i] {
  border: 1px solid green;
}

Result: With i flag, all three inputs match.

Why Use Case Insensitive?

Common Use Cases

  • Handling inconsistent attribute casing
  • Email domain matching (domains are case-insensitive)
  • Protocol matching (HTTP, Http, http)
  • Language code matching
  • User input normalization

Combining Attribute Selectors

You can combine multiple attribute selectors for powerful, specific targeting:

/* Select input that is both text type AND required */
input[type="text"][required] {
  border: 2px solid #667eea;
}

/* Select links with href containing "example" */
a[href*="example"][target="_blank"] {
  color: green;
}

Best Practices

✓ Do's

  • Use attribute selectors for semantic HTML - They work with data-* attributes beautifully
  • Combine with other selectors - Use element type for better performance
  • Prefer exact matches when possible - More performant than contains
  • Use case-insensitive flag (i) - For user-generated or inconsistent attributes
  • Document your selectors - Attribute matching can be non-obvious

✗ Don'ts

  • Don't rely solely on attribute selectors - Classes are still better for explicit styling
  • Avoid overly broad contains selectors - They can match unintended elements
  • Don't assume attribute presence - Always verify with browser DevTools
  • Don't use without element type - Always include element for specificity management

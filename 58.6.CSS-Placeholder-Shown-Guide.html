What is :placeholder-shown?

The :placeholder-shown pseudo-class selector matches form input elements that are currently showing their placeholder text. It's activated when an input field has a placeholder attribute and no user input has been entered yet, allowing you to style inputs based on whether they're empty or contain user data.

Core Concept:

  • Matches when placeholder text is visible (no user input)
  • Does NOT match once user starts typing
  • Requires the placeholder attribute to exist
  • Works with text-based input types (text, email, password, etc.)
  • Enables CSS-only form state detection without JavaScript
  • Perfect for floating labels and form feedback UI
Browser Support: Modern browsers (Chrome 47+, Firefox 59+, Safari 10.1+, Edge 79+). Older versions need fallbacks.

Basic Syntax & Structure

Fundamental Syntax

Select elements showing their placeholder text:

input:placeholder-shown { /* Styles applied when placeholder is visible */ border-color: #667eea; color: #999; } input:not(:placeholder-shown) { /* Styles applied when input has user text */ border-color: #28a745; color: #333; }

Combining with Other Pseudo-Classes

/* Placeholder shown AND focused */ input:placeholder-shown:focus { border-color: #764ba2; box-shadow: 0 0 0 3px rgba(102, 126, 234, 0.2); } /* Placeholder shown AND invalid */ input:placeholder-shown:invalid { border-color: #999; } /* NOT showing placeholder AND valid */ input:not(:placeholder-shown):valid { border-color: #28a745; }

With Placeholder Pseudo-Element

/* Style placeholder text when shown */ input:placeholder-shown::placeholder { color: #667eea; font-weight: 500; } /* Change placeholder color when focused */ input:placeholder-shown:focus::placeholder { color: #764ba2; opacity: 0.7; }

Targeting Multiple Input Types

input[type="text"]:placeholder-shown, input[type="email"]:placeholder-shown, input[type="password"]:placeholder-shown, textarea:placeholder-shown { border-color: #e0e0e0; background: #f8f9fa; } input[type="text"]:not(:placeholder-shown), input[type="email"]:not(:placeholder-shown), input[type="password"]:not(:placeholder-shown), textarea:not(:placeholder-shown) { border-color: #667eea; background: white; }

Common Use Cases

Floating Labels

Move labels above input when placeholder is hidden:

label { position: absolute; top: 12px; left: 10px; transition: all 0.3s ease; } input:placeholder-shown ~ label { opacity: 0; pointer-events: none; } input:not(:placeholder-shown) ~ label { top: -20px; font-size: 0.8em; color: #667eea; }
Form UX

Border State Indicators

Change border color based on empty/filled state:

input { border: 2px solid #e0e0e0; } input:placeholder-shown { border-color: #ccc; } input:not(:placeholder-shown) { border-color: #28a745; } input:focus { border-color: #667eea; }

Input Icon Styling

Show/hide icons based on input state:

.input-wrapper icon { opacity: 0; transition: opacity 0.3s ease; } input:placeholder-shown + icon { opacity: 0; } input:not(:placeholder-shown) + icon { opacity: 1; } input:focus + icon { color: #667eea; }

Form Instructions

Show/hide help text dynamically:

.help-text { display: none; font-size: 0.85em; color: #666; margin-top: 5px; } input:placeholder-shown ~ .help-text { display: block; } input:not(:placeholder-shown) ~ .help-text { display: none; }

Background Transitions

Subtle background change on input activity:

input { background: white; transition: background 0.3s ease; } input:placeholder-shown { background: #f8f9fa; } input:not(:placeholder-shown) { background: white; } input:focus { background: #f0f4ff; }

Best Practices

✓ DO:

  • Combine with :focus: Enhance experience for both empty and filled states
  • Use with :not(): Style both placeholder-shown and non-placeholder-shown states
  • Add transitions: Smooth animations improve perceived quality
  • Provide fallbacks: Use JavaScript for older browser support
  • Consider accessibility: Ensure labels remain accessible
  • Test with screen readers: Floating labels need proper ARIA labels
  • Maintain contrast: Placeholder text must be readable

✗ DON'T:

  • Rely solely on :placeholder-shown: Older browsers need JavaScript fallback
  • Hide labels completely: Accessibility requires visible or ARIA labels
  • Make placeholder text too subtle: It must be clearly distinguishable from input text
  • Use for critical validation: Combine with proper validation indicators
  • Overcomplicate styling: Keep visual feedback clear and consistent
  • Forget about mobile: Test touch interactions and virtual keyboards

JavaScript Fallback

For older browser support, detect input state with JavaScript:

// Check if :placeholder-shown is supported function isPlaceholderShownSupported() { const input = document.createElement('input'); return CSS.supports('selector(:placeholder-shown)'); } // Fallback for older browsers if (!isPlaceholderShownSupported()) { const inputs = document.querySelectorAll('input[placeholder]'); inputs.forEach(input => { input.addEventListener('input', () => { if (input.value) { input.classList.add('has-value'); } else { input.classList.remove('has-value'); } }); // Initial state if (input.value) { input.classList.add('has-value'); } }); } /* CSS for fallback */ input.has-value { border-color: #667eea; }

Related Pseudo-Classes Comparison

Pseudo-Class Description Triggers Use Case
:placeholder-shown Input showing placeholder text Placeholder visible (empty input) Empty state styling
:focus Element has keyboard focus User clicks or tabs to element Active state styling
:valid Input passes validation Content matches validation rules Validation feedback
:invalid Input fails validation Content violates validation rules Error feedback
:filled Input has a value (non-standard) User has entered content Filled state styling

Key Takeaways

  • State Detection: :placeholder-shown matches when placeholder text is visible (input is empty)
  • CSS-Only: No JavaScript needed for basic form state styling
  • Perfect for Floating Labels: Animate labels in/out based on input state
  • Combine with :not(): Use :not(:placeholder-shown) to style filled inputs
  • Works with ::placeholder: Simultaneously style placeholder text appearance
  • Enhanced UX: Provide visual feedback without JavaScript overhead
  • Modern Browser Support: Supported in all modern browsers except IE 11
  • Accessibility Matters: Always maintain visible or ARIA labels for screen readers

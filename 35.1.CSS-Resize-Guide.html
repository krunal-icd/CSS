🔄 CSS Resize Properties

Complete Guide with Interactive Examples

What is CSS Resize?

The resize property controls whether an element can be resized by the user

The CSS resize property allows users to change the width and/or height of an element. This is commonly used with textareas, input fields, and custom containers. The resize handle appears in the bottom-right corner and can be dragged to resize the element.

💡 Key Point: The resize property only works on elements that have an overflow value other than 'visible'. It's typically used with textareas and pre-formatted text elements.
Property Description Browser Support
resize: none Element cannot be resized (default for most elements) ✓ All modern browsers
resize: both Element can be resized both horizontally and vertically ✓ All modern browsers
resize: horizontal Element can only be resized horizontally ✓ All modern browsers
resize: vertical Element can only be resized vertically ✓ All modern browsers
resize: initial Sets to default value (browser dependent) ✓ All modern browsers
resize: inherit Inherits from parent element ✓ All modern browsers

resize: none

Disables resizing - element has a fixed size

Fixed Size No Resize Handle

Prevents users from resizing the element. The resize handle will not appear. This is useful when you want to maintain a specific element size.

Try to resize (you can't!):
/* Disable resize for textarea */ textarea { resize: none; width: 100%; height: 100px; }
💡 Use Case: When you need a fixed-size input field or want to prevent layout shifts caused by user resizing. Common in forms where consistency is important.

resize: both

Allows resizing in both horizontal and vertical directions

Both Directions Full Control

Allows users to resize the element both horizontally and vertically. The resize handle appears in the bottom-right corner as a diagonal arrow.

Try to resize both directions:
📍 Cursor changes to: se-resize (southeast resize)
textarea { resize: both; width: 100%; min-height: 120px; overflow: auto; }
Requirements:
  • Element must have overflow: auto or overflow: scroll
  • Cannot be used on elements with overflow: visible
  • Works best on block-level elements like <textarea>, <div>, <pre>
💡 Use Case: Code editors, text boxes, image containers where users need flexible sizing options.

resize: horizontal

Allows resizing only horizontally (width only)

Width Only Left-Right Drag

Allows resizing only in the horizontal direction. Users can change the width but not the height. The resize handle appears on the right edge.

Try to resize horizontally:
📍 Cursor changes to: e-resize (east resize)
textarea { resize: horizontal; width: 100%; height: 100px; overflow: auto; }
💡 Use Case: When you want to control only the width - like data grids or columns that should maintain a fixed height but allow horizontal expansion.

resize: vertical

Allows resizing only vertically (height only)

Height Only Up-Down Drag

Allows resizing only in the vertical direction. Users can change the height but not the width. The resize handle appears on the bottom edge.

Try to resize vertically:
📍 Cursor changes to: s-resize (south resize)
textarea { resize: vertical; width: 100%; height: 100px; overflow: auto; }
💡 Use Case: Most common for textareas in forms. Users can expand vertically to see more of their content while maintaining a consistent width.

resize: initial & resize: inherit

Default and inheritance behaviors

resize: initial

Sets to browser default. For textareas, usually allows both directions.

Parent: resize: both | Child: resize: inherit

Child inherits parent's resize behavior.

Parent (resize: both)
Child (resize: inherit) - Inherits resize: both from parent
/* inherit example */ .parent { resize: both; overflow: auto; } .child { resize: inherit; /* Inherits 'both' from parent */ }

🎯 Practical Examples

Real-world use cases and implementations

1. Feedback Form Textarea

Allow users to expand the textarea vertically as they type feedback.

textarea { resize: vertical; min-height: 120px; max-height: 300px; width: 100%; padding: 12px; border: 2px solid #667eea; border-radius: 6px; } textarea:focus { outline: none; border-color: #764ba2; box-shadow: 0 0 0 3px rgba(102, 126, 234, 0.1); }

2. Resizable Widget/Container

Dashboard widgets that users can resize to their preference.

📊 Resizable Widget

Drag the bottom-right corner to resize this widget. Both width and height can be adjusted.

.resizable-box { resize: both; overflow: auto; min-width: 200px; max-width: 600px; padding: 20px; cursor: se-resize; }

3. Code Editor

Simulate a code editor that can be resized both ways.

📝 code.js
/* Code editor */ .code-editor { resize: both; overflow: auto; background: #1e1e1e; color: #d4d4d4; font-family: 'Courier New', monospace; padding: 15px; border-radius: 6px; }

4. Responsive Container

Full-size resizable container for flexible layouts.

🔄 Drag to Resize
This container can be resized both horizontally and vertically
.resize-container { resize: both; overflow: auto; height: 250px; width: 100%; }

✨ Best Practices

Guidelines for implementing resize effectively

1. Always Set Overflow

The resize property only works when overflow is auto or scroll. Never use it with overflow: visible.

2. Set Min/Max Dimensions

Use min-width/max-width and min-height/max-height to prevent elements from becoming too small or too large.

3. Provide Visual Feedback

The cursor changes automatically, but you can also add hover effects or borders to indicate the element is resizable.

4. Consider Mobile Users

Resize handles may not work well on touch devices. Consider providing buttons or alternative resize methods for mobile.

5. Use Vertical for Textareas

For most textarea elements, resize: vertical is the best choice. It allows users to expand content visibility without changing layout.

6. Disable When Not Needed

Use resize: none for form fields where size should be fixed (like search bars or email inputs).

7. Test Resize Behavior

Test your resizable elements on different browsers and screen sizes to ensure consistent behavior.

8. Save User Preferences

Consider using localStorage or a backend to save user-resized dimensions for a better user experience.

⚙️ Important Requirements:
  • Element must have overflow: auto or overflow: scroll
  • Cannot be applied to display: inline elements
  • Works best with block or display: block elements
  • Resize handle appears in bottom-right corner
  • User must drag to manually resize (no JavaScript method)

🖱️ Cursor Behavior

How cursor changes with different resize values

Resize Value Cursor Style Handle Position Description
resize: both se-resize Bottom-right corner Diagonal arrow, resize in both directions
resize: horizontal e-resize Right edge Horizontal arrow, resize width only
resize: vertical s-resize Bottom edge Vertical arrow, resize height only
resize: none Default No handle No resize handle appears
💡 Tip: You can customize the cursor appearance using the CSS cursor property, though browsers typically handle this automatically.

🌐 Browser Support

Compatibility across modern browsers

The resize property is well-supported across all modern browsers. It was introduced in CSS 3 and has excellent compatibility.

✓ Full Support:
  • Chrome 1.0+
  • Firefox 4.0+
  • Safari 4.0+
  • Edge 12.0+
  • Opera 10.5+
  • All modern mobile browsers
⚠️ Note: While the resize property is supported by all modern browsers, the behavior on touch devices (mobile, tablets) is limited. Resize handles don't work well with touch - users will need to use alternative methods or responsive design instead.

❌ Common Mistakes

What NOT to do with resize property

❌ Using on inline elements

Mistake: span { resize: both; }

Fix: Use block elements like div or textarea.

❌ No overflow property

Mistake: div { resize: both; } (no overflow set)

Fix: Always add overflow: auto;

❌ No size constraints

Mistake: Users can resize elements to 0px or extremely large sizes.

Fix: Set min/max-width/height

❌ Overusing resize

Mistake: Making everything resizable can confuse users.

Fix: Use resize only where it adds value (textareas, editors, widgets).

❌ Ignoring mobile users

Mistake: Resizable elements don't work well on touch devices.

Fix: Provide alternative resize methods or disable on mobile.

❌ Poor UX without feedback

Mistake: No visual indication that elements are resizable.

Fix: Add borders, hover effects, or tooltips to indicate resize capability.
